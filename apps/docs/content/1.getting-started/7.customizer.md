## Open the customizer

Choose **Customize this layout** in the sidebar footer, or use the adjustments icon next to the color-mode button in either header. The color-mode button keeps its quick light/dark toggle.

Preview your changes as you make them. Keep your choices in this browser as you move between pages. Edit website text and metadata in your content and configuration files.

## Enable it in your app

You can try the customizer on this documentation site. Enable it in your own app with this setting:

```ts [app/app.config.ts]
export default defineAppConfig({
  indocio: {
    customizer: { enabled: true },
  },
})
```

Set `enabled: false` to hide the customizer and stop applying its saved preferences. You can also customize your site through app configuration and CSS.

## Appearance

Choose color mode, primary, accent, font, site size, and corner radius on the first screen. Check each row for its current value. Change primary or accent for the light or dark mode you are viewing.

Open **Colors & contrast** to choose background and text colors for **Primary**, **Secondary**, and **Accent**. Select **Light colors** or **Dark colors** to edit one mode. Use the main screen's mode buttons to preview System, Light, or Dark. Keep separate color choices for light and dark mode.

- **Colors:** Black, White, Neutral, Teal, Blue, Violet, Rose, Amber, Orange, and Green.
- **Site default:** remove that token's override and restore the app's CSS.
- **Foreground:** choose a text color, or let the customizer pick contrasting black or white text for your background.
- **Use primary:** choose this for the accent background to match your primary color. Set it for light and dark mode as needed.
- **Corner radius:** choose a preset on the main screen, or open **Typography** to use a slider or number input from 0 to 1.5rem.
- **Interface fonts:** Inter, Roboto, Open Sans, Lato, DM Sans, Source Sans 3, or system sans.
- **Code fonts:** JetBrains Mono, Fira Code, IBM Plex Mono, Source Code Pro, or system mono.

Use the listed webfonts through Nuxt Fonts. Serve the font files from your site and load a family when readers use it. Choose **Site default** to keep the fonts in your CSS.

Check the name and swatch in each dropdown to see your selected color. Choose primary, secondary, and accent colors for each mode. Use secondary colors for secondary controls and accent colors for smaller highlights.

## Sizes

**Site size** changes text, spacing, rem-based sizes, and controls on landing and documentation pages. XS is compact (87.5%), M is the normal scale (100%), and XL is spacious (112.5%). The selected size also sets the global IPEX control default, including the product dropdown. Touch controls keep a minimum 44px height.

Choose **Site default** to restore the app's scale. Explicit pixel dimensions stay fixed; rem-based dimensions scale with the site.

Open **Typography** to set **Reading text size** (12–22px), **Page title size** (24–48px), and **Code text size** (11–20px) using numeric inputs. Use these pixel sizes to set article text sizes apart from the overall site scale.

## Layout

Adjust article maximum width using a positive CSS length, such as `42rem`, `800px`, or `75ch`. Check the validation message if you enter an invalid width. Keep the last valid width until you enter a new one.

Move the TOC beside the article or to the screen's right edge. Adjust heading depth, sidebar width, desktop sidebar collapse, docs header height, TOC width and gap, and the product switcher style when the site has at least two documentation spaces. Sidebar and header/TOC dimensions use numeric inputs.

The article stays centered on screen. On smaller screens, readers can expand the table of contents above the page. Set the Markdown parsing depth in [Layout and configuration](/getting-started/layout) to include deeper headings.

## Visible elements

Show or hide the sidebar, TOC, breadcrumbs, footer, previous/next links, search, and copy-link action. The header's customizer trigger stays available even when the sidebar is hidden.

The layout and element controls apply to documentation pages. The appearance controls also apply to the landing page.

## Saved preferences and reset

Preview your browser preferences over the page, product, and site settings. Save the copied settings in your project files to share them with other visitors.

Choose **Reset** to clear your customizer changes, restore System color mode, and use the settings in your files. You keep saved preferences in this browser for this site. You can preview changes for the current visit even if the browser blocks storage.

Open a settings group to see its controls. Choose **Back** to return to the main screen. If you prefer less animation, enable reduced motion in your device settings.

You may see the site defaults for a moment on first load, before the browser applies your saved preview.

## Copy settings into your project

Choose **Get code** in the panel footer, then use the file-specific copy buttons. Copy the snippet for the file you want to update:

| Button                  | Destination           | Contents                                                     |
| ----------------------- | --------------------- | ------------------------------------------------------------ |
| **Copy main.css**       | `app/assets/main.css` | Formatted theme and typography CSS                           |
| **Copy app.config.ts**  | `app/app.config.ts`   | `defineAppConfig` with layout and product-switcher overrides |
| **Copy nuxt.config.ts** | `nuxt.config.ts`      | `defineNuxtConfig` with the color-mode preference            |
| **Copy ui.ts**          | `app/plugins/ui.ts`   | Global IPEX control-size configuration                       |

Choose a site size to enable **Copy ui.ts**. Apply the CSS and UI plugin snippets together to match the preview. If you have not changed the theme, keep your existing stylesheet.

Merge the copied configuration with your existing files. Add the CSS to your app's stylesheet.

Choose **Copy all (JSON)** to copy your settings together: `appConfig.indocio`, `css`, `colorMode`, and `uiConfig.defaults.size` if you changed the site size.

Use **Copy ui.ts** for the IPEX control size and **Copy main.css** for site scale and typography. Set the control size outside the plugin function so you use the same default on the server and in the browser:

```ts [app/plugins/ui.ts]
import uiConfig from '@igrislabs/indocio/ui-config'

uiConfig.defaults = { ...uiConfig.defaults, size: 'lg' }

export default defineNuxtPlugin(() => {})
```

Review the copied settings and commit them to your project to share the design with your readers.

Keep accent and branding CSS in your app. After saving the settings in your files, choose **Reset** to check the new site defaults.

## Custom triggers and overrides

Add `DocsCustomizer` for the panel and `DocsCustomizerTrigger` for its button. Use the default `compact` button in headers. Use `:compact="false"` for a labeled sidebar button.

The layer's `app.vue` mounts the panel once when enabled. If you replace `app.vue`, include `<DocsCustomizer />` when the customizer is enabled. If you replace `DocsHeaderActions` or `DocsSidebarBottom`, include `<DocsCustomizerTrigger />` where you want the entry point.

`useCustomizer()` exposes `enabled`, `open`, `preferences`, and `reset()`. Use `open.value = true` for a custom trigger. `reset()` clears the appearance and layout overrides; the panel's reset button also restores System color mode.
