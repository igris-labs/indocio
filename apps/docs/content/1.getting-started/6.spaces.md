## Mark a documentation space

A documentation space is a folder for one product or section. Create a space to give readers a separate sidebar and previous/next links for that product.

```text
content/
  index.yml
  platform/
    .navigation.yml
    introduction.md
    configuration.md
  cli/
    .navigation.yml
    installation.md
```

```yaml [content/platform/.navigation.yml]
title: Platform
description: Build and configure your application.
icon: tabler:box
space: true
redirect: introduction
docs:
  content:
    width: 46rem
```

Set `space: true` to give the folder its own navigation. Use `redirect` to choose the page readers open from the product selector. In the example, readers open `/platform/introduction`. Omit `redirect` to use the first visible page in content order.

Choose a visible page inside the product folder for `redirect`. You can use a relative path, such as `introduction`, or the full path, such as `/platform/introduction`.

Use numbered folders and filenames to set the reading order. Keep folders without `space: true` as sections in the existing sidebar.

## Add a product home page

Add `index.md` inside each product folder to give it a home page at `/inrux`, `/instruo`, or `/initera`:

```text
content/
  index.yml
  inrux/
    .navigation.yml
    index.md
    getting-started.md
  instruo/
    .navigation.yml
    index.md
  initera/
    .navigation.yml
    index.md
```

Mark each product as a space. For Inrux, create `content/inrux/.navigation.yml`:

```yaml
title: Inrux
description: Guides and reference for Inrux.
icon: tabler:box
space: true
```

Use the home page for a product introduction and links to key guides. Add cards or other Markdown components to give readers a starting point while keeping the product sidebar.

For example, write this in `content/inrux/index.md`:

```md
---
title: Inrux
description: Learn how to set up and use Inrux.
docs:
  toc:
    enabled: false
  navigation: false
---

## Start using Inrux

Follow the setup guide to create your first project.

::card{title="Get started" to="/inrux/getting-started" icon="tabler:book"}
Install Inrux and create your first project.
::
```

Open `/inrux` to see this page with the Inrux sidebar. Add an `index.md` to the other product folders for their home pages. Use `docs.toc.enabled: false` and `docs.navigation: false` on an overview page to hide the table of contents and previous/next links.

Use `content/index.yml` for the site's main landing page at `/`.

## Choose the switcher

```ts [app/app.config.ts]
export default defineAppConfig({
  indocio: {
    spaces: {
      switcher: 'dropdown', // 'dropdown' | 'tabs'
    },
  },
})
```

Choose `dropdown` for a menu or `tabs` for a row of product names. Readers see the selector once you have at least two spaces. They open the page you chose with `redirect`, or the first visible page in that space.

## Navigation and search

Inside a space:

- Browse the product's pages in its sidebar.
- Use previous/next links to read pages within the product.
- Check the breadcrumbs for your current product and page.
- Search within the product, or select **Search all documentation** to include other products in the current language.

Keep shared guides outside product folders to give them their own navigation. Readers can reach product pages through the selector or search.

## Translations

Put the same product folders inside `content/en/`, `content/cn/`, and your other language folders after you enable i18n. Translate each folder's `.navigation.yml`. Use relative `redirect` paths to keep readers in their selected language.

Switch languages to open the matching page. If you have not translated that page, readers open the product's entry page or the selected language's landing page.

Use the same folder names across languages to connect matching pages. Add a product's content in a language to include it in that language's selector.

## Product identity and versions

Keep the site name and header across products, and choose each product's label, description, icon, and `docs` settings in its `.navigation.yml`. For versioned guides, add links to the versions you want readers to use.
