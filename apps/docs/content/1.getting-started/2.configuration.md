## Landing page

Edit `content/index.yml` to change the landing page title, description, and links. Use links beginning with `/` to link within the current language.

```yaml [content/index.yml]
title: Documentation for your project
description: Everything you need to get started.
links:
  - label: Get started
    to: /getting-started/introduction
```

## Site identity

Set `indocio.name` and `indocio.description` in `app/app.config.ts`. Add your logo in `app/components/BrandLogo.vue` and your favicon in `public/favicon.svg`.

## Translations

Keep your pages in `content/` until you enable translations.

Enable i18n in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@igrislabs/indocio'],
  indocio: {
    i18n: { defaultLocale: 'en' },
  },
})
```

Move your content into `content/en/`, `content/cn/`, and `content/fr/`. Each language has its own `index.yml`, Markdown pages, and navigation files. Routes use language prefixes, including the default language, such as `/en/getting-started/introduction`.

Include the language prefix in links you write inside translated Markdown, such as `/fr/getting-started/configuration`.

## UI components

Use IPEX components with the `Ui` prefix, such as `UiButton`. To replace a documentation component, add a matching file in `app/components/docs/`. Add your own Markdown components in `app/components/content/` or Markdown renderers in `app/components/prose/`.

## Primary and accent

Choose a primary color for your main actions. Set an accent color for smaller highlights, or leave it unset to use primary. You can set different colors for light and dark mode.

Override `--primary` and `--primary-foreground` in your application's stylesheet to change the brand. Provide `--accent` and `--accent-foreground` only when you want a separate accent. Define `.dark` values as needed.

Use accent for small highlights such as navigation states, focus rings, and link underlines. Keep reading text neutral. Change accent without changing your primary or secondary colors.

## Layout and authoring

Read [Layout and configuration](/getting-started/layout) for article width, TOC placement, sidebar behavior, visibility, and edit links.

Read [Component overrides](/getting-started/overrides) to customize individual Docs components. Read [Multiple products](/getting-started/spaces) to give each product its own sidebar and search results.

Browse **Markdown components** in the sidebar for individual component pages with rendered examples, source Markdown, props, and slot usage. [Callouts](/components/callout) documents all callout variants together.

Use component names such as `code-tabs` in Markdown without imports. Pass text props as attributes. For arrays, objects, or numbers, use YAML or a bound prop such as `:columns="2"`. Write Markdown between the opening and closing component markers.

Use the [Live customizer](/getting-started/customizer) to preview theme and layout changes, then copy the settings into your application.

### Sidebar metadata and ordering

Set `navigation.icon` in a page's frontmatter to display its sidebar icon:

```yaml
navigation:
  icon: tabler:book
```

Organize the sidebar with your content folders and filenames. Use `.navigation.yml` to name a section. Add numeric prefixes, such as `1.introduction.md` and `2.installation.md`, to set a reading order. Use unnumbered filenames for alphabetical order.

Indocio uses Nuxt Content's navigation and page order. Readers see the pages for their selected language and product. You do not need to maintain a separate list of sidebar links.
